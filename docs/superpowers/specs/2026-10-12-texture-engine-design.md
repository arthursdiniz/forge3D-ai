# Independent Texture Engine

User intent: texture approved existing geometry later, with real appearance generation where compatible, immutable versions, safe external model import and Unity materials. Modeling quality is outside this task. User explicitly requests continuous inline execution; routine design/plan approvals are not additional gates. Public SDXL/MV-Adapter download and local testing was explicitly authorized in this conversation under OpenRAIL++/Apache2.

Architecture: extend Store opaque records with import/texture kinds, parent geometry provider retained for its license; texture provider recorded separately. Lightweight API routes validate requests/uploads. The existing serial Worker launches isolated CLI processes, preserves parents, handles cancellation and stages. No model inference in API.

Core: reuse xatlas/moderngl/reference projection. New texture_engine modules separate contracts, reference staging, UV validation, geometry equivalence, camera buffers, fusion/padding, materials, diagnostics, providers and execution. Per-instance/per-material atlases preserve world triangles and scene hierarchy. Existing valid UVs/data maps are preserved; re-unwrap with data maps requires an unsupported rebake and is refused rather than silently corrupting normal maps. UV overlap is measured; purely albedo/no-map meshes may receive new xatlas UVs. No geometry edits, merging, decimation or remesh.

Reference projection: named real front/left/back/right views; full-scene occlusion, face angle/confidence, bounded atlas padding and coverage/provenance masks. Unseen texels neutral. Alignment is estimated orthographic, explicitly uncertain. No fake neural filling/style specialization.

Neural candidate: official MV-Adapter SDXL image+geometry and text+geometry weights, pinned public resources. SD2.1 endpoint returned401, no gate bypass. Native trained six-view position/normal controls reproduced with moderate OpenGL rasterization and NumPy cameras; original neural adapter/weights unchanged. CV-CUDA/nvdiffrast postprocessing is replaced by local UV/projection/fusion, not by fake inference. Joint six-view inference remains intact. FP16/slicing/tiling/sequential or model CPU offload tested on4060; only a profile with actual successful inference, mesh application, geometry comparison and export proof is enabled. Hunyuan2.1Paint21GB/TRELLIS2Linux24GB alternatives remain unavailable here. No WSL/Docker/drivers/toolkits.

Import: GLB/GLTF(+local bounded sidecars),OBJ(+MTL/images),FBX via trusted Blender with disable-autoexec. Reject unsafe paths/URIs/unsupported resource types and static-pipeline inputs with skins/animations/morph targets. Model validation occurs in child; preserve uploaded originals. Unbundled external image links are detached before output. No blend files/scripts accepted.

Materials: preserve normal/AO/metallic-roughness/alpha when available; new albedo sRGB, data maps linear. Parameters per source material name, maps/factors provenance explicit. glTFMRG/B→UnityMetallicR/SmoothnessA conversion, normal setup and multiple renderer slots independently validated. Legacy single-material exports still work. AdvancedPBR disabled unless actually validated.

UI: separate Texturização IA workspace with library/import, capability-driven references/prompt/style/seed/resolution, stages/resources, before/after/clay/unlit/wireframe, atlas/coverage/maps and versions. No effectless controls. Existing modeling modes retained; explicit geometry-only TripoSR option avoids its color query/bake without requiring texture runtime.

Acceptance: real independent texturing of old and imported meshes, immutable source, world triangle equivalence, UV checks, occlusion/front-back fixtures, offline execution, cancellation/new-job retry, insufficientVRAM, normal preservation, GLB/FBX/OBJ and URP/Built-in material reimport. Neural success requires a real measured end-to-end run; otherwise honestly blocked. Full existing suite/build, browser desktop/mobile and one final fresh review.
